1. PROJECT GOAL (one paragraph)
================================================================================
Build the "HyDE + decision-model re-ranking" pipeline from the project Handbook
(HyDE_Clef_Project_Handbook.pdf, extracted to _handbook_text.txt, 69 KB).

In short: for 50 TREC-COVID topic queries, generate 8 hypothetical "answer"
passages each with a large language model, embed the mean of (query + passages)
with the Contriever dense retriever to freeze the top-100 candidate docs per
query, then RE-RANK those frozen candidates with a decision model
(pplx-decider) and a cross-encoder, and finally evaluate every system against
the gold relevance judgements.

The pipeline has 5 stages, mapped to numbered Python scripts in scripts/:
  Stage A  -> scripts/01_download_index.py   (build corpus index + FAISS)
  Stage 2  -> scripts/02_generate.py         (HyDE generation, 400 passages)
  Stage 3  -> scripts/03_retrieve.py         (embed + retrieve + freeze 5000)
  Stage 4  -> scripts/04_*.py                (RE-RANKING: NOT YET BUILT)
  Stage 5  -> scripts/05_evaluate.py         (evaluate + significance)

Stage 4 is the main remaining work (see section 11).

  but only one can be resident at a time on the 32 GB GPU).

  a real key for local model calls. Do not hunt for or store any key.

- MODEL A — the GENERATOR (Stage 2): exposed via vLLM as model "local-active".
  This is a hybrid REASONING model. Critical behavior:
    * It writes the abstract into chat.completions message.content.
    * It ALSO writes a separate "reasoning" trace. Only message.content is
      ever embedded (02_generate.py reads choice.message.content).
    * A system prompt named "suppress_reasoning_system" (the Handbook's
      "Answer directly ... Do not include any thinking..." prompt) is HARMFUL:
      it makes the model emit ONLY the reasoning trace, so message.content is
      None. THEREFORE the code sends a user-only prompt and NEVER uses that
      system prompt. (This is a Handbook-vs-reality conflict; reality wins.)
    * The reasoning trace consumes a lot of the token budget (observed ~100–
      1000 tokens), which is why max_tokens had to be large.

- MODEL B — the RE-RANKER / DECISION MODEL (Stage 4, not yet built):
  vLLM model name "pplx-decider-v1.1-27b" (config: reranker.model).
  It is invoked with question_type in {noul, score} and a "flash" variant
  exists too. SWITCHING to this model requires re-loading it on the vLLM
  server (the generator must be swapped out, because one model at a time).

6. DATA CONTRACTS (how artifacts are shaped — do not break these)
================================================================================
- Contract A/B (JSONL): hyde_docs.jsonl and candidates.jsonl are APPEND-ONLY.
  json helpers in common.py open JSONL in "a" mode by contract. If you need a
  fresh file, DELETE it first, then let the script recreate it. Do NOT make
  jsonl helpers overwrite silently — that silently corrupts the pipeline.
- hyde_docs.jsonl row schema:
    {qid, gen_idx, model, prompt_version, temperature, seed, text,
     n_tokens, truncated, created_at}
- candidates.jsonl row schema (5 fields, required by re-rankers & eval):
    {qid, docno, stage_a_rank, query, question}
- Contract C (TREC run files): "qid Q0 docno score runname" (rank is line
  order). Higher score = better rank. write_trec() produces these with "w"
  mode (overwrite), which is correct for run files — different from JSONL.
- evaluate.py cannot use ranx's built-in .from_file (it expects a 6-field
  line). It parses 5-field TREC itself and hands scores to Run.from_dict.
  Do not "simplify" this or 5-field runs will silently fail to load.

8a. Why nDCG numbers differ from the Handbook's reference
    -------------------------------------------------------
    The Handbook's BM25 reference is 0.656. That number is the Published BEIR
    reference for a DIFFERENT corpus (the Handbook lists 171,332 docs; our
    ir_datasets corpus has 192,509 docs reported, of which 191,132 have text).
    Our 0.5722 is correct for OUR corpus. I confirmed all 26,664 relevant

8b. One small cosmetic artifact to know about
    ------------------------------------------
    A few HyDE passages (8 of 400) have a trailing token that looks like
    "Word count: N" appended at the END of the text, produced by the prompt's
    "Write 80-120 words" instruction. It is HARMLESS for retrieval and fits
    inside the re-ranker's 6000-char state budget. If you want pristine
    abstracts, strip a trailing "Word count:" token in 02_generate.py before
    writing (easy). Not required for correctness.

9. MISTAKE(S) FOUND AND FIXED THIS SESSION (why the pipeline was NOT actually
   complete before, and what changed — READ BEFORE re-running generation)
================================================================================
When re-verifying "is Stage 1 really done?" (a request that triggered this),
the previously-produced HyDE set was NOT actually clean:
  (a) Every HyDE passage was truncated at the old max_tokens=224, because the
      model's separate reasoning trace (100-1000 tokens) ate the token budget
      and left the abstract cut off mid-sentence.
  (b) Some passages leaked markdown section headers (**Abstract**, Abstract:,
      **Background:**). Worse: the model emits STACKED headers, e.g. it writes
      `Abstract**` then a newline then `Background:**`. The old one-pass
      cleaner stripped only the FIRST header, leaving the second.

Fixes applied (already saved in the code):
  * config.yaml: generator.max_tokens 224 -> 1024 -> 2048. Reason: the model
    emits the abstract in message.content AND a separate reasoning trace; only
    2048 leaves room for both so none are truncated.
  * scripts/02_generate.py clean_generated() is now a LOOP that strips ALL
    leading headers/markdown in turn, and is careful to never strip a real
    body word (it only strips a header when followed by punctuation/markdown
    or a newline, never by a real word). This fixes both (a) truncation and
    (b) leaked/stacked headers. The regenerated set shows 0 truncation and 0
    header leaks.

These two changes are why the current hyde_docs.jsonl is clean. Re-running 02
without keeping them reproduces the bad set — so keep them.

10. HARD-WON RULES (non-obvious, do not relearn the hard way)
================================================================================
- NEVER use the "suppress_reasoning_system" system prompt. It forces the model
  to emit only the reasoning trace, leaving message.content = None. The code
  sends a user-only prompt and omits it. (Handbook says to use it; Handbook is
  wrong here.)
- Always read the abstract from choice.message.content. The "reasoning" is a
  separate field and must NOT be embedded.
- Use common.tokenize() for cheap deterministic tokenization (BM25). The
  private token regex is _TOKEN_RE — import via common.tokenize(), not the
  bare regex (the module does not export TOKEN_RE).
- Do not trust PDF numbers: corpus size (171,332 vs 191,132/192,509),
  max_tokens, reference BM25 (0.656), and stage numbering all differ from what
  actually works. Re-verify each claim against ir_datasets + the endpoint.
- Append-only JSONL: to regenerate a JSONL artifact, DELETE it first, then run
  the script fresh. Appending to a stale file silently bloats it.
- Run scripts with the venv python and the -u flag for unbuffered logs.
- A background job (e.g. generation) may still be running under a different PID
  than the notification reports. Check /proc/<pid>/cmdline before trusting a
  "process gone" notice.
